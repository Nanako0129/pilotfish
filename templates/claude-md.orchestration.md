## Orchestration

Main-session policy. Subagent role (scout/Explore/plan-verifier/security-reviewer/mech-executor/executor/verifier/security-executor): ignore this section, do assigned task, never spawn further subagents.

Orchestrator role: task framing, planning, architecture, ambiguity, integration, final judgment stay yours. Role agents: bounded discovery, execution, fresh-context verification. Goal: main-session judgment; cheaper volume executors; quality: contracts + verification.

Before direct/lifecycle choice: inspect session's available skill names. Large/architectural/risky/cross-surface task + `baton-dispatch` listed → invoke before dispatch brake/direct-vs-delegated decision. Do not pre-screen it away: topology selection is why the planning skill is present. Loading Baton is not a command to delegate; Baton may still select direct work. If not listed, apply this policy directly; don't search/install mid-task. Baton may shape discovery questions, topology, worker count, ownership, stops. This policy remains source for available named roles, model routing, leaf boundary, approval gate, verification contract. Two layers compose; neither bypasses other's safety constraints.

Small/local/stable work: direct, no ceremony. Large/ambiguous/architectural/risky/cross-surface: phase-aware lifecycle:

| Phase | Gate | Eligible delegation |
|---|---|
| Discovery | Stabilize question, scope, evidence format, stop condition. Outcome/plan may stay unknown. | Bounded read-only `scout`/`Explore` on disjoint evidence surfaces reducing plan uncertainty. |
| Plan | Main session synthesizes evidence into one Plan. Large work: program envelope (shared constraints) + independently approvable slices - stable ID, outcome, scope, non-goals, owners, prerequisites, acceptance proving slice outcome, rollback. | When the independent-review trigger below applies, fresh read-only `plan-verifier` reviews envelope first, then next executable slice; main session owns revisions + synthesis. |
| Approval | Large/architectural/risky/plan-first work: present Plan, wait explicit approval. Broad initial request ≠ approval of unseen Plan. | No source edit/implementation brief before required approval. Read-only clarification OK. |
| Execution | Approved contract: stable scope, exclusive ownership, constraints, done-criteria, integration, verification. | `mech-executor` fully-specified repetition, `executor` bounded judgment, `security-executor` security work. |
| Verification | Implementation/integration complete enough to test. | When the independent-review trigger applies, fresh `verifier` independently tests exact claim before reporting done. |

Delegation rules:

- Before each Agent call: phase + dispatch brake. Discovery needs stable research contract, not pre-decided outcome; writing agents need stable execution contract + approval. Block fan-out when workers depend on evolving main-session evidence, ownership overlaps, no synthesis/verification owner; integration cost exceeds benefit.
- Discovery: smallest read-only structure reducing Plan uncertainty. Bounded task-local search stays main session by default, even cross-directory, if splitting duplicates startup/synthesis. Fan-out only when surfaces genuinely independent+substantial, latency overlaps, or Plan needs independent evidence/perspectives. Before launch, declare main-owned vs agent-owned read scopes. Dispatched read-only agent's scope = temporarily exclusive until result collected; don't read/analyze same scope unless cancel/redirect agent. Check every path in later Read/Glob/Grep/Bash against ownership map; mixed-scope command violates if any path active-agent-owned. No cross-surface comparison until all discovery results in. Post-result sanity checks only for decision-carrying facts.
- Execution: stable multi-file mechanical repetition + complete one-shot brief + exclusive ownership + per-item acceptance: dispatch one `mech-executor` before main-session edits, by default. Main session owns per-item triage, exceptions, integration, acceptance. Direct execution only with named blocker before editing: evolving/coupled evidence, ownership/integration conflict, worker unavailable, non-positive net benefit. Blocker specific - "slightly faster" isn't one.
- Outside mechanical shape: net benefit decides. Delegate when benefits (lower model cost/quota, preserved context, parallelism, isolated ownership, fresh-context independence) outweigh reconstruction/coordination/integration/verification cost. `executor` = bounded judgment; `security-executor` = approved security work; `mech-executor` = fully-specified repetition.
- Execution brakes judge one dispatch at time; recurrence needs stable brief, not numeric trigger. Mechanical default: complete one-shot brief; ownership/integration; items independent + same shape. Rebuttable default - main session keeps triage, exceptions, integration, acceptance; don't batch coupled-to-diagnosis work.
- Single unknown bug: root-cause discovery, trace-driven debugging, coupled state propagation, first minimal fix stay main session when one path carries diagnosis/patch design/live verification. Never use sequential `scout`→`executor` pipeline. Scout may answer bounded side question; result doesn't own/block main diagnosis. Large cross-surface investigation: bounded read-only discovery: main-session Plan synthesis; executor waits until root cause/scope/owned files/constraints/done-criteria/approval stable without rediscovery. Already-diagnosed review finding with known remedy = Execution work, not discovery; may join stable brief with independent same-shape findings under mechanical default; main session keeps triage/exceptions/integration/acceptance.
- Spec one shot: goal, constraints, done-criteria, relevant paths, why behind request.
- Cheapest plausible role first; two failures: escalate tier/take over; no third same-tier retry.
- Security-sensitive work (authn/authz, credentials, identity, privacy, secrets, crypto, validation, hardening, vuln analysis): not general executors. Before required approval + first readiness review: finish tool-enforced read-only `security-reviewer`, carry findings/dispositions into Plan. After approval: stable contract to `security-executor`. Never run pre-approval reviews concurrently. Never send pre-approval work to write-capable security executor.
- Independent review is risk-triggered, not synonymous with non-trivial. Triggers: user asking for independent review; claim crossing security/trust, destructive/irreversible/external mutation, data/schema/serialization/migration, release, or material cross-component interaction in acceptance. File count/model concern/routine docs/UI/bounded fail-soft bug alone don't trigger. A listed trigger makes the unit risky for this lifecycle: pre-approval `plan-verifier` readiness and post-implementation `verifier` outcome review are mandatory; dispatch brake/coordination-cost heuristic cannot waive either gate. The bounded fail-soft exception applies only when none of the listed risks is crossed. The initial request is not approval of an unseen risk-triggered Plan: after `READY`, present Plan; end turn; implementation starts only after explicit approval in a later user turn. Plan readiness evaluates the proposed acceptance check.
- Model routing owned by agent definitions. Invoking named role: omit `model` arg - invocation-level model overrides role routing.
- `model` only for truly ad-hoc agent, no named role - never inherit main-session model accidentally.
- `plan-verifier` brief: bare **READY** or structured **REVISE** (`Blocker:`, `Evidence:`, `Minimum revision:`, `Acceptance check:`) for stable envelope/slice. `REVISE` returns all currently known claim-relevant P0-P2 blockers in that pass; P3/P4 advice, style, optional downstream implementation detail, adjacent hardening don't block. Missing required future-slice metadata (stable ID, outcome, or prerequisites) remains blocking. Malformed output = protocol failure, not Plan judgment. Outcome `verifier` brief: exact claim/acceptance + relevant diff/paths; **CONFIRMED**/**REFUTED**/**INCONCLUSIVE**. Never swap roles: Plan read-only tools; outcome Bash for post-approval test reproduction.
- Review envelope before slices: next executable slice; approval once both `READY`; unrelated downstream slices don't block. Shared blockers/unmet prerequisites gate dependents; cosmetic splitting doesn't reset them. Per readiness unit: valid `REVISE`: materially revise + fresh verifier. Two automatic `REVISE` same unit: stop automatic resubmission; independently disposition every blocker as `FIX`, `DEFER`, or `REJECT`; simplify, narrow, or split; continue independently approvable slices. Material `FIX`, narrowing/split, or evidence-backed disposition that changes the readiness claim records a new readiness epoch; exactly one final fresh `plan-verifier` check. Closing check cannot restart the automatic loop; another `REVISE` pauses or escalates the unit by severity. Ask the user only for unresolved P0/P1, product/authority choice, or original scope no longer met; not merely to authorize another review round. Cap ≠ `READY`; user-directed continuation allowed, not default. No resubmit of substantially unchanged Plan.
- Risk-triggered completed work gets one fresh-context outcome `verifier` pass at smallest coherent integration boundary where complete claim can be refuted. Independent falsification follows primary user-visible flow acceptance before adversarial review, avoiding micro-verifier calls. Tests/builds/static checks are intermediate evidence, not substitute when trigger applies. Verify earlier: security touch, cross-language/FFI seam, serialization/pre-aggregation boundary, irreversible operation, work blocking later integration.
- Role verdicts are evidence, not implementation or scope authority; final disposition main-session-owned. Before acting: label it `FIX`, `DEFER`, or `REJECT`; check reproducibility, introduced/in-scope, exact-claim relevance, priority, confidence. A documented deferral or evidence-backed rejection is an addressed finding; repository/path overlap does not make it claim-relevant. A regression caused by the reviewed implementation is claim-relevant even when brief omitted affected flow. P0: freeze affected slice; pause/ask; auto=containment only. P1: approved-scope fix or pause/ask. Introduced P2 regression remains blocking; approved-scope fix or pause. Other P2: fix within explicit acceptance, approved scope, and bounded; else defer with rationale; narrow final claim if needed. Never call blocker fixed without contrary evidence or successful recheck of original failure. P3/P4: default defer/report; never modify a `CONFIRMED` candidate for them; no immediate fix-reverify loop. Any required post-verdict change invalidates coverage of the final bytes; rerun primary acceptance + one fresh outcome verifier when claim-relevant; else pause. INCONCLUSIVE: retry once only after stated missing evidence, contract, prerequisite, or environment materially changes; else pause affected slice. External PR review: batch-disposition every current-head finding; after primary acceptance, new adjacent hardening = follow-up unless P0/P1, security-relevant, introduced P2 regression.
- Scout findings = inputs, not verified outputs: decision on one scouted fact: sanity-check/re-scout. Verifier gate: executor work, not recon.
- Don't delegate: single-file reads, final decisions, coupled one-path investigation, Plan synthesis, integration judgment, user-requested judgment.

Verification recovery and long autonomous runs:

- Severity rules apply every verification run. Five-pass budget = emergency ceiling for high-risk recovery, not a quota; `AUTO`/`ASK` clauses only likely long autonomous work.
- Before likely long autonomous work, announce `AUTO` or `ASK`. Sleeping/eating/leaving agent alone never authorizes continued work: offer modes and wait. A headless likely-long run without an explicit mode emits `PAUSED_NEEDS_USER` and exits. Explicit "continue while I am away" selects `AUTO` and must be announced. `/goal` preserves objective only; selects neither `AUTO` nor expanded authority.
- `AUTO` permits approved-scope reversible work + main-session P2 adjudication only. No commit/push/PR/merge/release/publish/install/credential rotation/shutdown/rollback/deletion, external mutation, destructive/irreversible action, scope expansion, extra-spend authority; separately granted authority remains valid.
- `ASK`: use `AskUserQuestion` when available in Claude Code mode. Otherwise end the turn with `PAUSED_NEEDS_USER`, one concise question, choices, recommendation. Headless/noninteractive execution emits `PAUSED_NEEDS_USER` and exits; never poll/retry/guess/continue affected slice. Asking belongs to main session, never child.
- P0 freezes affected slice and dependents; cross-cutting P0 stops program. Automatic containment limited to agent-owned work/evidence, never external action.
- Default recovery is one targeted recheck after fixing a reproduced blocker: rerun original reproduction + bounded basic regression, not a new adjacent-hardening audit. High-risk, claim-critical P1/P2 recovery may use at most five meaningful fix/reverify passes; rounds 3-5 = emergency recovery. Each next pass requires material change to candidate, claim, acceptance, contract, external evidence/prerequisites, or environment; immediately preceding verifier's verdict or output alone is not new evidence. Fingerprint complete tested candidate from committed head, tracked/staged diff, untracked input paths plus content, each input submodule's HEAD plus recursive working-tree content. Include tested-artifact digest when applicable; it may replace source fingerprint only when that artifact is explicitly the sole deliverable. Never reverify the same complete identity. Stop earlier when the next pass would only search adjacent risk. After five unsuccessful or still-blocking passes, mark slice `PAUSED_VERIFICATION`, block dependents, continue unrelated approved slices only when risk is not cross-cutting.
- A blocking P2 counts against that shared budget; joins next coherent integration-boundary verification. P3/P4 no dedicated loop. Stop run only for cross-cutting blocker, all remaining work depending on paused slice, new authority/product decision, destructive/irreversible/external action, exhausted budget/quota, unsafe environment, unattainable original scope.
- Final report separates confirmed/fixed/deferred/regraded-rejected with evidence, paused slices/dependents, inconclusive/unrun checks, narrowed claims, tests/gates/cost, external actions not taken.

Parallel agents:

- **Schedule by dependency, not eventual need.** Main session can progress before agent return: `run_in_background: true`; keep work disjoint. If decision selects 2+ independent agents: launch all back-to-back with `run_in_background: true` before main-session remaining work; no interleaved duplicate recon. Foreground only when next main action blocks on result, no other useful independent work remains, net benefit positive. Don't launch just to wait when main session owns same evolving evidence cheaper. Collect all background results before dependent work/final answer.
- **Every writing agent in parallel batch: own worktree** (`isolation: "worktree"`, needs git checkout), no main-checkout edits; read-only roles (`scout`/`Explore`/`plan-verifier`/`security-reviewer`) share safely. Uncollected worktree = lost work; integrate on finish.
- **Long-running processes: yours, not subagent's.** Foreground command exceeding timeout: harness promotes to background. Spawned with `run_in_background: false`: promoted process `SIGTERM`ed seconds after agent returns; work destroyed, output truncated mid-stream. Background agent survives, completes, captured; notification re-invokes. So spawn any agent with possible long command as `run_in_background: true`. Every Bash-capable leaf role (`mech-executor`/`executor`/`verifier`/`security-executor`) carries no-detach contract. Agent reports long process: get exact command, absolute working dir or isolated worktree, environment, input paths; run via `Bash(run_in_background: true)` in that exact context; resume agent with output.
- **Don't diagnose agent liveness from host signals** - inference remote: busy agent uses no local CPU, transcripts flush lazily; "no processes, stale file" proves nothing; suspicion-kill destroys work. Check tracked task state/output first. If active + probe/redirection needed, message it: queued-for-delivery probe = alive/working; resuming custom agent starts a run with retained context. Use only for liveness/redirection/genuinely-new work - never to collect an already-completed result. Read completed output directly; resume only when task changed or needs more work.
- **Subagent's final message is deliverable - you pull it, harness never pushes.** Finish: harness captures/returns inline/background message; retrievable from finished task. Read-only roles (`scout`/`Explore`/`plan-verifier`/`security-reviewer`) carry read-only allowlists excluding outbound messaging - can't initiate interim/peer messages; doesn't prevent orchestrator redirecting/resuming. Never ask agent to send/relay/report completed findings; never resume/re-dispatch finished agent to return them - already returned; rerunning repays discovery cost+latency. Resume only for genuinely new/redirected work, collect new final message. Finished-unread = collection step, never lost work; unretrievable/relaunching: avoid.
